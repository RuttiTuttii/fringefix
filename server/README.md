# приёмник отчётов fringefix

принимает отчёты, которые пользователь сам отправил из окна «Отчёт и статистика», проверяет их по белому списку и складывает файлами. Только стандартная библиотека Python 3.10+.

> ограничения: приёмник не аутентифицирует клиентов, любой может отправить отчёт. Защита это проверка схемы, лимит размера, не больше 5 отчётов в час на адрес и общий потолок хранилища. Адрес клиента сервер видит, но нигде не записывает. Сам эндпоинт живёт в бинарнике публичного exe, поэтому секретом он не является.

## интерфейс

| метод и путь | ответ |
| --- | --- |
| `POST /v1/reports` с `Content-Type: application/json` до 16 КБ | `201 {"id": "202611-a1b2c3d4e5f6"}` |
| `GET /v1/health` | `200 {"ok": true}` |

снаружи тот же путь с префиксом `/fringefix/api`. Коды ошибок: 400 битый JSON, 411 нет длины, 413 больше 16 КБ, 415 не JSON, 422 не прошла проверка, 429 лимит (с `Retry-After`), 507 хранилище заполнено.

## что хранится

по файлу на отчёт в `/var/lib/fringefix-reports/ГГГГ-ММ/` с правами 0600. В имени только месяц и случайный номер. В файле только поля из `fringefix_reports/validate.py`, всё остальное отбрасывается при приёме. Ни адреса, ни точного времени, ни заголовков запроса в файле нет.

## развернуть

```bash
# из папки server: выложить пакет, юнит systemd и блок в Caddy, проверить снаружи
./deploy/deploy.sh msk_direct moscow.fragmentzal.store
```

скрипт делает копию `Caddyfile`, вставляет блок `handle_path /fringefix/api/*` в сайт, проверяет `caddy validate` и при ошибке возвращает копию. Сервис работает под временным пользователем с изоляцией systemd (`DynamicUser`, `ProtectSystem=strict`, пустой набор capabilities).

после выкладки в репозитории GitHub нужна переменная `REPORT_URL`, её CI подставляет в сборку:

```bash
# адрес приёма попадает в exe при сборке; в исходниках его нет
gh variable set REPORT_URL --body "https://moscow.fragmentzal.store/fringefix/api/v1/reports"
```

## сводка по отчётам

```bash
# версии, видеокарты, ошибки и игры по сеансам и минутам
python3 -m fringefix_reports.summary /var/lib/fringefix-reports
```

## тесты

```bash
# проверка, хранилище, лимит и HTTP целиком на временном порту
python3 -m unittest discover -s tests -t .
```

`tests/fixtures/report_v1.json` создан настоящим кодом клиента на C, поэтому тесты проверяют, что сервер принимает именно то, что отправляет программа.
